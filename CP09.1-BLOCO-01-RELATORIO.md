## 2. Alterações aplicadas

### 2.1 Carregamento sob demanda das telas
Seis módulos de tela passaram a usar `React.lazy()` e importação dinâmica:
- Perfil;
- Minha Academia / Equipamentos;
- Biblioteca de Exercícios;
- Biblioteca de Temas;
- Planos de Treino;
- Evolução.

Foi adicionado `Suspense` com estado de carregamento acessível para telas e carregamento sob demanda do modal de temas. Dashboard, navegação, cabeçalho e provedores permanecem no carregamento principal para manter a entrada e a estrutura global disponíveis.

**Importante:** a separação em chunks foi implementada no código, mas a redução real do bundle inicial ainda precisa ser medida com `vite build`, indisponível nesta execução por falta das dependências instaladas.

### 2.2 Limpeza de imagens legadas sem referência
Foram removidos 43 arquivos JPEG antigos de `src/assets/images/` (29.231.631 bytes, aproximadamente 27,88 MiB). A busca por nomes exatos em arquivos de código, configuração e documentação do projeto não encontrou referências a nenhum deles.

Os arquivos ativos do catálogo não foram alterados:
- 180/180 imagens de exercícios preservadas;
- 54/54 imagens 3D de equipamentos preservadas.

A remoção reduz o peso do pacote-fonte; não representa uma redução equivalente do bundle de produção, pois esses JPEGs não eram referenciados pelo código.

### 2.3 PWA e funcionamento offline
A configuração de pré-cache foi preservada. O padrão continua incluindo JS, CSS, HTML, ícones, PNG, SVG e WebP, mantendo a exclusão de `assets/aistudio`. Os chunks gerados pelas importações dinâmicas continuam sendo arquivos JS elegíveis ao padrão de pré-cache.

Nenhuma alteração foi feita nos bancos IndexedDB, seus nomes, versões, stores ou dados do usuário.

## 4. Pendências para homologação completa

O `npm install` não concluiu dentro do limite de execução; a tentativa offline confirmou que as dependências não estão disponíveis no cache local (`ENOTCACHED`). Por isso, nesta execução não foi possível rodar `npm run build`, `npm test` completo com `tsx`, medir os chunks gerados, nem executar a validação visual em navegador e PWA instalado.

Antes de declarar CP09.1 homologado, ainda devem ser verificados:
1. `npm install` / restauração das dependências;
2. `npm run build` e comparação do tamanho dos chunks;
3. navegação entre as seis telas e abertura do modal de temas;
4. atualização preservando a tela;
5. instalação/atualização PWA e abertura offline;
6. treino ativo, persistência e integridade dos dados locais.
